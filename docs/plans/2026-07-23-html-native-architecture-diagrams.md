# HTML-Native Architecture Diagrams Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make report architecture diagrams directly editable as semantic page HTML while retaining automatic node sizing and reusable connector rendering.

**Architecture:** The report owns all groups, nodes, labels, and graph edges as HTML plus adjacent JSON. CSS Grid performs coarse layout and automatically sizes nodes. A small shared renderer reads the HTML graph, asks vendored jsPlumb Community to attach orthogonal connectors, and applies only declarative edge attributes such as anchors, connector type, color, and arrow policy.

**Tech Stack:** Semantic HTML, CSS Grid, jsPlumb Community 6.2.10, browser DOM, Node regression spike, Firefox visual verification.

## Global Constraints

- Preserve the accepted M1 visual hierarchy and all downstream report figures.
- Node content and group structure must be editable in `docs/html/interactive-ranker-v2.html`.
- Diagram-specific JavaScript must not contain node labels, graph topology, coordinates, or source-target routing branches.
- Ordinary edges must need only source and target IDs; exceptional anchors remain declarative data.
- Node text must remain selectable HTML.
- Vendor the pinned browser dependency under `docs/html/js/vendor/`; do not add a repository package manager.
