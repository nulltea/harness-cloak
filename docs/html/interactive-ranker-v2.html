Interactive Ranker v2Semantic policy architecture and structured reinforcement learning

normative design report · 2026-07-23
Abstract

Interactive Ranker v2 is a selected, unvalidated architecture for choosing KEEP, truthful lattice generalizations, or placeholders under a user-selected privacy-utility setting. A frozen clinical encoder provides complete-document context and ordered source-to-candidate semantics. Separate trainable branches produce a utility logit and a profile-relative predicted privacy score; an explicit additive \(\lambda\) controller combines them without exposing true counts to the actor. Training uses full round-trip task utility, assertion-routed document RLOO, sparse one-decision counterfactual correction, and exact own-profile count shaping restricted to the controller scale. Count remains an experimental proxy; final method comparisons require held-out attacker outcomes at matched realized privacy.

§01

Introduction

objective · separation · status

Ranker v2 chooses one legal rewrite per controlled value while keeping task utility, semantic privacy prediction, exact count shaping, and realized privacy evaluation as four distinct objects.

The policy acts on each distinct detected value in a document. It may keep the source text, choose a truthful lattice generalization, or use a typed placeholder. Utility is measured only after the complete privacy round trip: rewrite doc_orig into doc_p, run the remote task, locally unperturb out_p, and score out_final. Privacy pressure comes from a separately pretrained semantic head that predicts how the candidate changes the source profile's log count.

The architectural rule. The utility tower never sees true counts, predicted privacy, lattice position, menu size, or \(\lambda\). The privacy head never sees document context, task assertions, action history, or \(\lambda\). Their outputs meet only in an explicit additive controller. This blocks the direct metadata shortcut in which the actor can optimize count reward without learning the candidate's meaning.

Status. This page documents the selected prototype and the normative RL design. Reward-flow and semantic-v1 model implementations exist in the main worktree, but representative real-data validation and the architecture promotion gates remain incomplete. Count shaping is experimental. Realized privacy is still measured by a held-out inference or re-identification attacker on doc_p and out_final. Interim: production runs currently inject direct grounded counts as the controller's privacy score while a proper k-anonymity estimator model is trained; the figures deliberately keep depicting the semantic privacy head (see the spec's implementation-status section).

Computing architecture rendering…

The policy scores one candidate rewrite at a time by asking two independent questions — does this wording preserve what the document is about, and how much anonymity does it buy — and lets a single transparent knob decide how far the second answer may move the first.

Scoring one action. A frozen clinical encoder reads the whole document once, and the vector it produces for every token is kept — one row per token, computed once and reused by every decision in that document. That cache is the token bank (H_doc in the figure, sized tokens × 768); no part of the policy fine-tunes the encoder that produced it. Each candidate action is written out as an ordered relation — [TYPE] health-condition · [SOURCE] kidney transplant · [CANDIDATE] solid organ transplant — and pushed through that same frozen encoder, so a candidate is always represented relative to the value it would replace rather than as a free-standing phrase. Two small trainable projections then split that relation vector: one serves the utility path, the other the privacy path, and neither can modify the other's features.

The utility side turns its projection into a query and attends three times over the cached document: over summaries of the occurrences this decision controls, over the chunks containing them, and over every token in the document. A cross-attention block additionally looks up the decisions already made for this document. The concatenated readout, the relation, and their explicit interaction pass through one MLP to a single number, the utility logit \(u(a)\).

The privacy side sees only the relation. It predicts a standardized log of the candidate's anonymity-set size, \(\mu_{\log K}(a)\); dividing by the largest predicted value in the current profile's own menu converts it into profile-relative privacy progress \(\hat{p}(a)\) in \([0,1]\), with KEEP pinned at \(0\) and the typed placeholder at \(1\). The two sides meet exactly once, in an additive controller — \(z(a,\lambda) = u(a) + \alpha\, g(\lambda)\, \hat{p}(a)\) — after which dynamic legality masks unavailable fills and a log_softmax over the legal menu yields the action distribution.

Separate branches are not enough on their own. Two modules mean nothing if every loss updates both, so gradient ownership is explicit: utility and counterfactual losses update the utility tower and its memory; the exact count objective updates only the controller scale; privacy calibration updates only the privacy projection and head. The privacy head stays frozen through the first hybrid run so count pressure cannot quietly redefine what \(\hat{p}\) means. The controller scale is the one deliberate exception — it receives both utility and count gradients, because with privacy gradient alone its optimum would be unbounded privacy tilt. At \(\lambda = 0\) the controller contributes exactly zero, so combined logits are bitwise equal to utility logits; this is an architectural identity, not an initialization that training could erode.

Design decisions

Privacy signal — a semantic head, not the count itself. The head predicts a candidate's log-count from the source-to-candidate relation and normalizes it within that profile's own menu, so privacy pressure is an inspectable quantity the actor never sees. Predicting it rather than reading it off an artifact is what lets the policy score wording it has never encountered, and normalizing within the profile keeps the score meaningful when count scales differ between profiles. Also considered: one \(\lambda\)-conditioned scorer over all features, and strict type-normalized grounded counts — the latter retained as the more auditable fallback.

\(\lambda\) conditioning — one global scalar, applied after both branches. A single trainable \(\alpha\) weights a fixed transform \(g(\lambda) = \log(1{+}\lambda)\,/\,\log(1{+}\lambda_{\max})\), which buys three things at once: \(\lambda = 0\) is exactly the utility policy by construction rather than by initialization, one checkpoint serves the whole operating menu, and the privacy weight stays legible because a scalar signal is matched by a scalar knob. It is also the smallest form that can fail informatively — if one \(\alpha\) cannot produce distinct operating points, the fork reopens instead of quietly growing capacity. Also considered: full-representation FiLM, privacy-only FiLM, per-profile slopes, profile embeddings, separate profile heads.

Document context — read per candidate over the whole document. A candidate-conditioned query attends over the token bank — every token of the document, each encoded with both its left and right context — so two candidates for the same decision retrieve different evidence and the model can judge whether this generalization survives this document. Bidirectional and full-length both matter: clinical explanations often follow the mention rather than precede it, and the dependencies that decide utility are frequently nowhere near the span. Freezing the encoder is what makes that bank reusable at all, and keeps a readout gain distinguishable from corpus memorization. Also considered: local CLS plus occurrence mean, bidirectional local target-span pooling, a unidirectional state at the span, full fine-tuning or LoRA, a candidate-rendered cross-encoder.

Candidate features — encoded jointly with the value they replace. Type, source, and candidate go through one frozen pass, are pooled per field, and become an ordered vector carrying the signed difference and elementwise product. Encoding the pair rather than the phrase is the whole point: generality is a relation, not a property of wording, and the ordering makes kidney transplant → solid organ transplant distinguishable from its reverse. Because the vector has no parameters of its own, the two branch projections downstream cannot leak into each other. Also considered: candidate text alone, an independent bi-encoder, retrieval and synonymy embeddings (SapBERT, MedCPT, MedEmbed, NeuML), with BioLORD-2023 held as the first escalation.

Encoder checkpoint — one frozen clinical encoder, pinned to an immutable revision. BioClinical-ModernBERT-base adds clinical-note and biomedical pretraining while keeping the same architecture and 768-wide interface the policy already used, so it is a drop-in at base-model cost, and pinning the revision makes it part of the experiment's identity and cache key. One caveat travels with it: this encoder saw all of ACI-BENCH during pretraining, so ACI can support development and training but cannot be used to select an encoder or to claim out-of-corpus generalization. Also considered: the large variant, ClinicalMosaic, Clinical_ModernBERT, Bio_ClinicalBERT, PubMedBERT, and plain ModernBERT-base as a non-clinical control.

Action history — earlier decisions stored, not summarized. Prior selected actions stay as an explicit set that the current candidate queries by cross-attention, so a candidate can retrieve the one earlier choice that bears on it and ignore the rest. This matches the environment's semantics — the rewrite is assembled from the whole action vector, so semantic choices are not intrinsically ordered — and the memory therefore carries source position but no selection-step index, making the policy invariant to row order. With 4–38 decisions per document, one attention block is cheap. Also considered: no history at all (retained as the baseline that must be beaten), a count-blind GRU, a Decision Transformer.

Privacy-head objective — fit the mean, quarantine the uncertainty. The controller consumes only the predicted mean, so the head optimizes exactly that: a deterministic mean on train-standardized log counts plus direct calibration of the profile-relative score the controller will actually use, with profiles weighted equally so no large menu dominates. Uncertainty is estimated once after the fact as a single clamped residual scale, which keeps it reportable for audit without letting variance calibration gate a controller that never reads it. Also considered: a learned heteroscedastic \(\sigma\), negative log likelihood as a blocking gate, an unbounded logistic rank loss.

Shapes and parts

One number sets almost everything: the frozen encoder's hidden size, 768. The trainer reads it from the encoder manifest and derives the rest, so there are no independently tuned widths that can drift apart.

  • Working width — 768. Relation, context, history, and utility-hidden dimensions are all the encoder's hidden size, so everything the policy passes around is a 768-vector.
  • Relation vector — 3840. Five times the width, because the ordered pair vector concatenates five fields: type, source, candidate, candidate − source, and source ⊙ candidate.
  • Attention heads — 8 (falling back to 1 if the width were not divisible by 8), with dropout 0 throughout.
  • Three context reads. Independent attention modules over occurrence summaries, target-containing chunks, and every document token; their outputs concatenate and project back to 768.
  • One memory block. A single eight-head cross-attention over 768-wide rows of prior selected actions, returning an exact zero vector when the memory is empty.
  • Privacy projections — 256 by default; a loaded privacy checkpoint carries its own widths.
  • No normalization layers. There is no LayerNorm, batch normalization, or residual block anywhere in the model. The only normalizations are profile-menu normalization of predicted log counts and the final legal-action log_softmax.

Hyperparameters

Two of these were measured rather than chosen — the controller scale and the \(\lambda\) menu. The rest are conventional defaults carried unchanged, and are named as such rather than presented as tuned.

Controller.

  • \(\alpha\) — the controller scale, and the only trainable parameter outside the two towers. It converts profile-relative privacy into logit pressure, as \(\alpha = \mathrm{softplus}(\alpha_{\mathrm{raw}})\): one global scalar shared by every document, action, runtime type, and \(\lambda\). It is deliberately the smallest form that can express a privacy–utility tilt, so that failing to produce distinct operating points is a reportable result rather than something more capacity would paper over. Training pulls it from both sides, since utility and exact-count gradients both reach it, and it is frozen in the checkpoint before held-out evaluation.
    Calibration: the default carries the value over from the behaviour-cloning checkpoint. The adopted candidate measures it instead: for each decision, the smallest controller pressure that would move the argmax off the utility-preferred action onto a more private one, \(\min_j (u^* - u_j)/(\hat{p}_j - \hat{p}^*)\) over the more-private actions; each threshold is divided by that menu's utility-logit range, and the document-weighted median across behaviour-cloned menus becomes the initial \(\alpha\).
  • gap — a scale match, not a free parameter. The detached per-menu utility range \(\mathrm{stopgrad}\big(\max_a u(a) - \min_a u(a)\big)\) multiplies the controller term. It exists because the raw controller measurably stopped working: at \(\alpha = 1\) the shift could not move behaviour-cloned utility logits at all — the selected count score sat at roughly 0.135–0.15 at every profile including the strongest, while \(\alpha\) drifted about 1e-3 per eight epochs, leaving \(\lambda\) behaviourally disconnected on trainable timescales. Expressing pressure in units of the menu's own utility spread makes the controller track the tower instead of being diluted as the tower sharpens. It was adopted against a preregistered rule over four composition-diverse documents spanning 4 to 22 decisions, twelve epochs, eight rollouts, one screening seed and two confirmation seeds, requiring exact \(\lambda\)-zero identity, a non-decreasing selected count score across profiles, and at least a 0.20 gain from the weakest to the strongest profile, among eight criteria.
    Computation: recomputed from the current legal menu at every forward pass as the detached spread of its utility logits, and detached so it contributes no gradient. There is no value to pick — the mechanism is only switched on or off by flag.
  • \(g(\lambda)\) and the \(\lambda\) menu — fixed, not learned. \(g\) is the deterministic transform \(\log(1{+}\lambda)/\log(1{+}\lambda_{\max})\), and its shape is doing two specific jobs: \(g(0) = 0\) is what makes the \(\lambda\)-zero identity hold by construction rather than by initialization, and dividing by \(\log(1{+}\lambda_{\max})\) sets \(g(\lambda_{\max}) = 1\), so \(\alpha\) means exactly "controller pressure at the strongest supported profile" instead of an arbitrary scale. The menu is finite and ordered so one checkpoint can serve every operating point.
    Derivation: each document's cached utility–privacy trajectory points are de-duplicated, weakly dominated points dropped, and an upper convex envelope taken; every adjacent pair on that envelope yields the \(\lambda\) at which the frontier winner changes, \((u_{\text{left}} - u_{\text{right}})/(p_{\text{right}} - p_{\text{left}})\). Those switch points are pooled with each document carrying equal total weight, read off at fixed quantiles in log-\(\lambda\) space (0.25, 0.60, 0.90 for a four-value menu) with zero prepended, and values producing identical action vectors are merged. The candidate menu is replayed across the pool and rejected unless it clears the frozen feasibility gates — adjacent-profile winner change, a placeholder ceiling, per-corpus document support, per-type decision support — with at most two replacement passes. The deployed values (0, 0.48, 1.05, 1.53) passed with zero replacement passes.

Hybrid RL objective.

  • \(\beta\) — entropy weight, default 0.01. It is there to keep probability mass on legal alternatives so a rollout group does not collapse onto a single trajectory. On the evidence so far it is not achieving that: the small-document diagnosis found its effect negligible beside rollout degeneracy, where whole groups return identical action vectors and every leave-one-out advantage is exactly zero.
    Provenance: a conventional default, carried unchanged and never swept.
  • \(\eta\) — KL weight, default 0.01. It anchors the policy to its warm-started behaviour. What matters more than the weight is what it anchors to and when it applies: the reference checkpoint is captured after controller calibration, because an uncalibrated reference would pull the controller back into the dead regime, and the default schedule arms KL only once an epoch's measured adjacent-profile winner-change falls below the frozen threshold in the manifest. The alternative keeps it on from epoch zero, adopted after that trigger proved too coarse to rescue an already-saturated policy.
    Provenance: the weight is a conventional default, carried unchanged and never swept; the reference and schedule are deliberate choices recorded in the decision log.
  • G — rollouts per document group. It sets how many complete round trips each leave-one-out advantage is computed over, so it governs both credit quality and run cost: too few rollouts and duplicate trajectories drive the advantage to zero, killing the utility gradient outright.
    Provenance: supplied explicitly per run with no default, precisely because it is the cost knob and should be a visible choice; an opt-in mode derives it per document instead, scaling by the dominant-trajectory probability.
  • Learning rate — 1e-4 with AdamW for both behaviour cloning and hybrid RL, with one behaviour-cloning epoch by default.
    Provenance: conventional defaults, carried unchanged and never swept.

Wired but off by default. Per-decision \(\alpha\) routing, gap scaling, switch-calibrated \(\alpha\) initialization, support-scaled rollouts, degeneracy-driven counterfactual coverage, always-on KL, reverse KL, a utility-logit softcap, and profile-sensitivity regularization all exist in the trainer behind flags whose defaults preserve the older behaviour, so enabling one is visible in the run command rather than implied by a code change.

How privacy changes selection

\(\log\frac{\pi(a)}{\pi(b)} = u(a) - u(b) + \alpha\, g(\lambda)\, \mathrm{gap}\,\big(\hat{p}(a) - \hat{p}(b)\big)\)

At \(\lambda = 0\) the code takes a separate branch: combined logits are identically the utility logits, not merely a numerical zero bias. At larger \(\lambda\), a candidate needs enough predicted privacy gain to overcome any utility disadvantage.

Why the head is pretrained. Profile-held-out count supervision forces the head to learn source-to-candidate abstraction before policy optimization. It must beat authored position, action mode and type, stable identity, and candidate-only baselines. The validated head is frozen during hybrid RL so the policy cannot bend \(\hat{p}\) into an uncalibrated preference.

Privacy pretraining loss. \(\mathcal{L}_{\text{privacy}} = \mathcal{L}_{\text{nll}} + \rho\, \mathcal{L}_{\text{rank}} + \gamma\, \mathcal{L}_{\text{huber}}(\hat{p},\, p)\). The likelihood preserves approximate count magnitude and uncertainty, the pairwise term checks ordering within a profile menu, and the Huber term calibrates the score consumed by the controller.

What exact counts do. Exact level_counts do not select actions directly and do not update the utility tower. They evaluate the current privacy contribution over the complete legal menu and update only the global scale \(\alpha\). Utility gradients oppose unbounded privacy pressure and also reach \(\alpha\), allowing one scalar to settle the useful range of the finite \(\lambda\) menu.

Computing training-process rendering…

Training is a sequence of stages, each buying one property the next stage depends on, and each freezing what it produced before the next begins.

Why it is staged at all. The policy has to learn two different things — which rewrite preserves meaning, and how much anonymity a rewrite buys — and the second must not be allowed to teach the first. Doing them together is exactly the shortcut the architecture exists to block, so they are separated in time as well as in structure: the privacy head is trained and frozen before the policy sees a single reward, and the controller that lets privacy influence a decision is switched off until the utility policy already works on its own.

Freeze the environment first. One versioned environment covers the detector span artifact, action menus, own-profile counts with provenance, accepted QA assertions, and the remote model, task prompt, extractor, reader, scorer, concurrency regime, and caches. These freeze together because they fail together: changing any one of them invalidates cached utility, the \(\lambda\) calibration, and every trained-policy comparison at the same time. Two load-time transforms then shape the initial-RL corpus — only drug, health-condition, and medical-procedure decisions are ranker-controlled, with out-of-scope or count-uncovered decisions demoted to fixed KEEP, and documents carrying no policy-role reward mass are dropped from training.

Supervised warm start. The behaviour-cloning teacher is a hand-written walk, not a model: for each decision it takes the finest legal lattice level, or the typed placeholder when no level is legal, claiming fills as it goes. The policy is fit to those actions by cross-entropy over each dynamic legal menu at \(\lambda = 0\), which gives it a legal, support-preserving starting distribution rather than a random one. Expert iteration then lifts it above the teacher on utility alone: sample G complete rollouts at \(\lambda = 0\), score full round trips, keep a winner only if it strictly beats the behaviour-cloning reference and survives a serial reverification pass with a fresh reader, then clone every action of that verified winner once. Neither stage sees \(\lambda\) or a count.

Then calibrate, in this order. The \(\lambda\) menu and threshold manifest are frozen from the cached utility–privacy trajectory pool; the controller scale is calibrated against the warm-started policy's own menus; and only then is the KL reference checkpoint captured. The order is forced by a measured failure: anchoring KL to an uncalibrated reference pulls the controller straight back into the regime where \(\lambda\) changes nothing.

The hybrid episode. One document, one \(\lambda\), G rollouts. Each rollout walks the decisions in first-occurrence order, emits a complete action vector, and is rendered into doc_p; the remote model answers; local inversion produces out_final; context assertions are scored on doc_p and delivered assertions on out_final, against a fixed policy-role denominator, with monitoring assertions scored and reported but never credited. Advantages are leave-one-out within the group, sparse counterfactual reruns replace individual terms with measured causal differences, and the exact count objective reaches only the controller scale. One honest caveat: on small documents the group frequently degenerates — every rollout returns the same action vector, so every leave-one-out advantage is exactly zero and the utility gradient dies. That is an open fork, not a solved problem.

Design decisions

Stage order — privacy frozen before policy, controller off until utility works. Pretraining the privacy head on held-out profiles and freezing it means the exact-count objective can never quietly redefine what the privacy score means during RL; starting the controller at zero means the utility tower is trained on its own merits first. Both are what make a later comparison across operating points interpretable at all.
Also considered: training everything jointly from the start.

Warm start — a deterministic teacher, not a learned one. A hand-written finest-legal-level walk is cheap, reproducible, and needs no model of its own, and cross-entropy against it leaves probability mass on every legal action rather than collapsing onto one. It is \(\lambda\)-independent, so a single warm start serves every operating point.
Also considered: beginning hybrid RL directly from a randomly initialized policy, which reopens the quantized-reward and tied-group failure that motivated a warm start in the first place.

Expert iteration — utility-only, and deliberately coarse. Selecting winners by document utility alone keeps privacy pressure out of the initializer entirely, and requiring a strict win over the behaviour-cloning reference plus a fresh-reader reverification stops reader noise being cloned as signal. Its labels are knowingly approximate — a winning trajectory carries passenger actions — because the hybrid stage exists to correct them with linked credit and counterfactuals.
Also considered: counterfactually filtering every winner before cloning, and dropping expert iteration altogether.

Operating points — one checkpoint over a finite \(\lambda\) menu. Three to five pre-registered values, \(\lambda\) held fixed for a whole document group, and no behaviour promised between them. One checkpoint keeps training cost and deployment simple while still exposing a real frontier, and a finite menu means every published operating point is one that was actually trained and replayed.
Also considered: a separate checkpoint per \(\lambda\), and a continuous \(\lambda\) slider.

Episode schedule — a seeded balanced Latin cycle. Over each block of \(|\Lambda|\) epochs every document is trained once at every supported profile, so a difference between operating points cannot be an artifact of which documents or types happened to be drawn at which \(\lambda\).
Also considered: independent random sampling of \(\lambda\) per episode, which is explicitly disallowed rather than merely discouraged.

Credit — episodic for utility, analytic for counts. The two objectives are kept on separate paths instead of being collapsed into one document scalar. Utility has to stay episodic because the remote model consumes the whole rewritten document and span choices interact through semantics and the injectivity mask; the count score, by contrast, is known in closed form for every legal action, so it is optimized as an exact local expectation rather than sampled — spending rollout variance on a quantity already known would be wasteful.
Also considered: broadcasting one combined document reward to every selected action, and training independent per-span utility rewards.

Objective shape — additive, with coefficients fixed per run. The loss is utility plus a privacy-shaping term rather than a \((1-\lambda)U + \lambda P\) blend, which keeps the utility scale constant as \(\lambda\) moves and keeps entropy and KL coefficients comparable across profiles. They are fixed per run and never rescaled per \(\lambda\).
Also considered: the convex-blend form, and per-profile coefficient tuning.

Training data — QA assertions

The reward is not one score. Each document carries a frozen vector of assertions, and they are measured at two different points in the round trip: context assertions read the anonymized document \(doc_p\), and delivered assertions read the final answer \(out_{\text{final}}\). Splitting them is deliberate — a placeholder-heavy rewrite can still produce a well-formed note that satisfies the delivered checks while destroying the relations a reader needed, so the two families are not collapsible into one number. The ACI artifact currently holds 1357 accepted assertions: 634 context and 723 delivered. Weight budgets are split equally across fact groups and then across each group's assertions, and the document's denominator is fixed, so a missing family costs utility rather than being renormalized away.

Context assertions — can the relation still be recovered from \(doc_p\)? Each is a question plus a required property pinned to one linked decision, and it scores as a binary: 1 while the reader can still recover that property from \(doc_p\), 0 once it cannot. That is the whole training signal — the assertion's weight is either collected in full or forfeited in full. They are proposed from the source document, then filtered by a three-point reader gate that renders the same question against three versions — the original document, a representative anchor with every linked decision at its required level, and an all-placeholder floor — and keeps the assertion only if the first two are answerable and the floor is not. That last condition is what makes an assertion discriminative rather than free: it must become unanswerable when the content is destroyed. Each row also freezes a relation-constrained reader clause that is reused verbatim at gate time and at runtime, so the gate and the reward use the same instrument.

Arguments. Every relation has one subject and one or more objects, and each argument is either a span — a controlled occurrence carrying a decision and a lattice profile, which the ranker can rewrite — or a literal, uncontrolled source text that is never rewritten and so appears verbatim in every render. The signature above shows each argument as it appears in doc_orig. Because a literal survives even the all-placeholder render, it can never be the answer: span → literal is not a live question shape. Compound forms exist too — {literals} → span, {spans} → span, and set-valued span → {spans} scored by per-member recall.

Level pinning. Notice that the highlighted locator in each question is not the source surface: cervical radicularopathy is asked about as "spinal radiculopathy", muscle strain as "the sprain". A span locator is never named by its raw surface, because the ranker may rewrite that surface — a question quoting it could not be grounded in doc_p. Deterministic rows pin the locator at the finest legal level: it is the given premise rather than the measured fact, so the most specific wording that survives rewriting maximizes the reader's ability to find it. The answer side is pinned the other way: required_property is the coarsest level that passed the reader gate, which is why the ladder scores 1 from the source surface up through that level and 0 beyond it. So QA defines a band and rewards any ranking inside it; the pull toward the coarse end comes from the count objective, not from QA. That division of labour is deliberate.

Ladder. Each assertion is a step function over the answered span's own levels: every rung scoring 1 is free privacy, and the first rung scoring 0 forfeits the assertion's entire weight from that document's utility, so the policy's job is to stop on the last rung still scoring 1. How far that reaches is not uniform — the depression row tolerates every level and only fails at the placeholder, while the MRI row loses its weight one rung up. One known gap: the question freezes the locator at one level while the policy is free to render that decision at any level, and the reader's ability to bridge the two was never certified across levels — so reward could be maximised by ranking the locator decision at exactly the frozen level, a preference the gate never checked for. Literal locators are immune, since they are never rewritten.

Delivered assertions — did the answer survive the round trip? These are deterministic and adapter-owned: their truth comes from the human reference note or the fixed task schema, never from a teacher's interpretation of the output. Four kinds, in descending count:

  • content (606) — a reference-backed controlled value must reappear in \(out_{\text{final}}\); this is the omission channel. Examples: contains "congestive heart failure", contains "kidney transplant", contains "autoimmune panel".
  • field (94) — exact agreement on parsed note fields against the reference, for example DEMOGRAPHIC · age = "50-year-old".
  • structure (14) — required sections present and parseable, for example HISTORY OF PRESENT ILLNESS · ASSESSMENT · PLAN with the expected labelled-row shapes. Its share is capped by a structural budget so formatting compliance can never stand in for semantic retention.
  • exact_relation (9) — a PLAN row still carrying its expected treatment and test, for example condition Arthritis with treatment "Initiate Ultram 50 mg every 6 hours as needed." and test "We will order an autoimmune panel for further evaluation."

Which assertions actually pay. Role is decided per document at scoring time, not baked into the artifact: an assertion is policy-role only if it depends on a decision this ranker actually controls, and everything else is monitoring — scored and reported, never credited. The policy-role weight mass is the denominator \(Z_d\) that utility is measured against. One family is currently demoted wholesale: exact_relation is forced to monitoring because it measured a zero pass rate on real remote notes, making it unwinnable by any action and therefore signal-free even where it is dependency-linked.

Credit assignment and loss

Document utility does not become one undifferentiated advantage. QA dependencies route cheap provisional evidence to the decisions that may matter. Sparse one-decision interventions then correct the highest-value uncertain cases.

Utility objective

\(U(g,Q) = \textstyle\sum_q w_q\, u_g[q] \,/\, Z_d\)

\(Z_d\) is the fixed policy-role weight mass; monitoring assertions never enter it.

\(A[g,j] = U[g,j] - \operatorname{mean}_{g' \neq g} U[g',j]\)

No standard-deviation normalization. A constant assertion supplies no gradient.

Counterfactual pair

\(q_{\text{pair}} = \pi(a) / \big(\pi(a) + \pi(b)\big)\)

\(\mathcal{L}_{\text{cf}} = -\Delta U \cdot \big(q_{\text{pair}} - \tfrac{1}{2}\big)\)

The pairwise loss favors the measured better action and is bounded as confidence grows.

Exact count view. \(\pi_{\text{count}} = \mathrm{softmax}\big(\mathrm{mask}(\mathrm{stopgrad}(u) + \alpha\, g(\lambda)\, \mathrm{gap}\, \mathrm{stopgrad}(\hat{p}))\big)\). The dense objective is the negative expected exact target over every legal action, weighted by \(\lambda / |D_d|\) and the same rollout-group factor \(1/G\). Only \(\alpha\) receives this gradient.

Overall loss. \(\mathcal{L} = \operatorname{mean}_d \mathcal{L}_{\text{utility}}(d) + \mathcal{L}_{\text{count}} - \beta\, \mathrm{entropy} + \eta\, \mathrm{KL}(\pi \,\|\, \pi_{\text{ref}})\). Counterfactual terms replace their corresponding provisional utility terms; they are not averaged into a separate unweighted bonus.

Scheduler. Counterfactual budget first covers decisions with no linked assertions, then multi-decision links and uncertain or stale measured pairs, while reserving nonzero probability for every eligible decision. Adjacent finer or coarser actions are preferred, with a pre-registered minority of KEEP and placeholder endpoint tests.

Utility score ties by design

What a tie is. Two actions on the same decision are tied when both preserve every QA-probed answer, so the reader scores the document identically either way. An exact tie measures \(|\Delta U| \le 10^{-9}\); a second band, \(0 < |\Delta U| \le 0.044\), sits below the independently measured reader-resolution floor and is indistinguishable from reader noise. Ties are not rare. In the full-corpus census, 18% of measured decisions are exactly flat and a further 21% are sub-noise — roughly 39% at or below the floor — and 33% of documents carry six decisions or fewer, where a single tie dominates the episode. This is a first-class regime, not a corner case.

Why the reward is deliberately silent there. The lattice and the QA artifact were built so that several generalization levels of the same span can all preserve the probed answers; when they do, only the count preference \(\hat{p}\) separates them. That silence is a design decision, on two grounds. It reflects task semantics: levels that keep every task-relevant answer are equivalent for the consumer of \(out_{\text{final}}\) — utility measures task preservation, privacy preference measures generalization depth, and those are different axes. And it protects the decomposition: awarding partial utility credit by depth would teach the \(\lambda\)-blind tower a privacy ordering, which is wrong by construction at \(\lambda = 0\), double-counts the count signal at \(\lambda > 0\), distorts \(\lambda\) semantics, and corrupts the matched-realized-privacy comparison the project rests on. One qualification bounds the claim: passing the current probes means equivalent for the measured artifact, not universally, so false equivalence from QA incompleteness is the residual risk — richer partial credit is legitimate only if it measures actual answer degradation, never lattice depth as a proxy for it.

Counterfactuals are a sensor, not a tie-breaker. On an exactly tied pair no channel supplies a utility ordering: leave-one-out advantages between tied rollouts are zero, the pair loss \(-\Delta U \cdot (q - \tfrac{1}{2})\) vanishes at \(\Delta U = 0\), and the count score is detached from \(u\) by construction. The sharper statement is that nothing with utility semantics controls that margin, while everything else — other documents sharing features, the KL and entropy regularizers, the sensitivity term — stays free to move it, so tied margins churn unless something else owns them. What the probes do contribute is exactly two things. They rescue dead groups: when every sampled rollout ties, all leave-one-out advantages vanish and counterfactual pairs are the only per-decision credit left, which is why small documents train at all. And they measure tie structure: each probe writes an evidence row — document, decision, pair, \(\Delta U\), surrounding-context hash — and the verified-tie labels distilled from it drive the tie-ownership machinery. Reward silence becomes an explicit, labelled fact; the zero itself still orders nothing. Ordering inside a tie is deliberately the controller's job, because the desired order is \(\lambda\)-dependent and the tower is \(\lambda\)-blind.

The coarse boundary is learned; the inside of the set is not. Silence holds only within the equivalence set. Past its edge the tower does receive ordering gradient, through both channels. Structural-neighbour probes test the levels adjacent to the selected one plus the KEEP and placeholder endpoints, so once the policy sits at the coarsest preserving level the adjacent-coarser probe measures the drop directly — a "one step further is bad" gradient at exactly the cliff edge. And on-policy sampling at high \(\lambda\) drags trajectories across the boundary, where broken answers cost document utility and are punished by leave-one-out advantages. Measured over one screening run, 57% of 498 probes were live pairs (up to \(|\Delta U| = 0.68\)) and 43% exact zeros — most probe gradient is boundary supervision, not silence. Three caveats bound that: exposure is progressive rather than exhaustive, since probes walk outward from the current policy and the cliff is only reached once the controller has pushed the policy to its edge; the penalty is fractional, because document utility aggregates assertions and a too-coarse level forfeits only the assertions linked to it; and the ~13% of decisions with no linked assertions can never teach coarse-is-bad at all. The net division of knowledge is that the tower learns where utility ends but not what is equivalent — inside the set the margins stay arbitrary, and carrying that measured equivalence to unseen documents is an open fork rather than a settled mechanism.

One local pass. The caller chooses one supported \(\lambda\) before ranking. The policy initializes empty selected-action memory and walks the frozen decision sequence. Dynamic legality removes any level fill already reserved or claimed. The model scores all actions in the complete menu, gathers the legal action IDs, and applies log_softmax. Deployment uses deterministic argmax.

Decision-level action, occurrence-level rewrite. Selecting one action updates every occurrence mapped to that decision. The selected utility relation, action mode, runtime type, and source-position pool become one history row for later decisions. Repeated occurrences do not create repeated policy steps.

Remote boundary. Ranking itself uses no QA probes, reader, reward model, exact count target, or counterfactual call. Only doc_p reaches the remote task model. The substitution record R stays local and combines with out_p to produce out_final.

§07

Boundaries and Audit

what the design means · what it does not prove

Normative invariants

  • \(\lambda = 0\) exactly equals utility logits before masking.
  • True counts never enter semantic actor features.
  • Exact count gradients cannot update utility or memory.
  • Privacy-head training cannot update utility features.
  • QA links route credit but never certify causality.
  • Uncovered decisions never default to zero utility credit.

Open empirical questions

  • Can semantic log-count prediction transfer to unseen profiles?
  • Can one global \(\alpha\) realize useful distinct operating points?
  • Does frozen candidate-conditioned attention expose enough context?
  • Does selected-action memory improve multi-decision utility?
  • Does higher count score track lower realized attacker success?
  • Does first-occurrence factorization create material order effects?

Repeated-context leakage. The exact document count score averages once per distinct policy decision, so repeated mentions do not multiply count reward. This is an explicit approximation, not a claim that repetition is harmless. Repeated values in different contexts may increase linkage or inference risk and require a future occurrence-aware attacker audit.

Fallback architecture. If semantic privacy transfer fails or stricter count auditability is required, the retained factorized fallback uses grounded type-normalized counts directly in a separate privacy branch. It remains count-blind on the utility side, but it does not offer the semantic prototype's transfer claim.

Verdict rule. Count score, KEEP rate, lattice depth, and \(\lambda\) are diagnostics. A method is compared only by utility versus held-out attacker success at matched realized privacy and identical settings. If count score rises while attacker privacy worsens, the approximation is falsified in that region and the failure is reported rather than calibrated away.
