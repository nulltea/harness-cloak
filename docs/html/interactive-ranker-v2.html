Interactive Ranker v2Semantic policy architecture and structured reinforcement learning

normative design report · 2026-07-23
Abstract

Interactive Ranker v2 is a selected, unvalidated architecture for choosing KEEP, truthful lattice generalizations, or placeholders under a user-selected privacy-utility setting. A frozen clinical encoder provides complete-document context and ordered source-to-candidate semantics. Separate trainable branches produce a utility logit and a profile-relative predicted privacy score; an explicit additive lambda controller combines them without exposing true counts to the actor. Training uses full round-trip task utility, assertion-routed document RLOO, sparse one-decision counterfactual correction, and exact own-profile count shaping restricted to the controller scale. Count remains an experimental proxy; final method comparisons require held-out attacker outcomes at matched realized privacy.

§01

Introduction

objective · separation · status

Ranker v2 chooses one legal rewrite per controlled value while keeping task utility, semantic privacy prediction, exact count shaping, and realized privacy evaluation as four distinct objects.

The policy acts on each distinct detected value in a document. It may keep the source text, choose a truthful lattice generalization, or use a typed placeholder. Utility is measured only after the complete privacy round trip: rewrite doc_orig into doc_p, run the remote task, locally unperturb out_p, and score out_final. Privacy pressure comes from a separately pretrained semantic head that predicts how the candidate changes the source profile's log count.

The architectural rule. The utility tower never sees true counts, predicted privacy, lattice position, menu size, or lambda. The privacy head never sees document context, task assertions, action history, or lambda. Their outputs meet only in an explicit additive controller. This blocks the direct metadata shortcut in which the actor can optimize count reward without learning the candidate's meaning.

Status. This page documents the selected prototype and the normative RL design. Reward-flow and semantic-v1 model implementations exist in the main worktree, but representative real-data validation and the architecture promotion gates remain incomplete. Count shaping is experimental. Realized privacy is still measured by a held-out inference or re-identification attacker on doc_p and out_final.

§02

Ranker Model Architecture

semantic-v1 · implemented computation graph
FIG · M1: Ranker v2 semantic policy architecture green = embedding/tensor · rust = linear · blue = attention · gray = normalization

The implemented policy is a shallow, factorized attention model over frozen 768-dimensional clinical representations, not a Transformer stack.

The current trainer fixes relation_dim = context_dim = history_dim = utility_hidden_dim = 768, uses eight attention heads, and sets dropout to zero. The ordered relation vector concatenates type, source, candidate, signed difference, and elementwise product fields, so pair_dim = 3840. The semantic privacy checkpoint controls its own projection widths; the current training CLI defaults both to 256.

Context readout. The document projection is summed with role, signed relative-position, and document-position embeddings. A candidate query drives three independent nn.MultiheadAttention modules over occurrence summaries, target-containing tokens, and every source token. Their outputs concatenate and project back to 768 dimensions.

Selected-action memory. Each earlier selected decision becomes one 768-wide key/value row. The current candidate's relation and document context form the query. One eight-head cross-attention layer returns a candidate-specific history vector. Empty memory returns an exact zero vector.

Normalization. The current model has no LayerNorm, batch normalization, or residual MLP blocks. The only normalizations are semantic profile-menu normalization of predicted log counts and the final legal-action log_softmax.

Controller parameters. The trainable scalar alpha = softplus(alpha_raw) scales the fixed g(lambda) transform on the deployed privacy-bias path. By contrast, gamma weights profile-relative Huber calibration only while pretraining the privacy head. It is absent from policy inference and hybrid-RL logits.

§04

Training Architecture

frozen semantics · trainable readout · explicit control

The same pinned clinical encoder serves two cached paths. The document path encodes every source token in overlapping chunks. The relation path jointly encodes runtime type, source surface, and candidate wording. Frozen shared computation is followed by separate trainable utility and privacy projections, so branch-specific supervision cannot modify the other branch.

FIG · T1: Training-time semantic and gradient separation green = frozen · blue = utility · red = privacy · rose = lambda control

Complete document observability. The frozen encoder is thomas-sounack/BioClinical-ModernBERT-base at revision c3648aa87af95837c809e6f0c5f85d08160db437, with hidden size 768 and remote model code disabled. It processes the entire document in 512-token inputs with 64 source-token overlap and no silent truncation. Target markers distinguish the current decision, other controlled occurrences, ordinary tokens, relative target distance, and source position. Candidate queries retrieve target, local, repeated-occurrence, and long-range evidence from the cached token bank.

Candidate semantics. The pair input is ordered as type, source, then candidate. Field means, signed candidate-minus-source features, and elementwise products preserve both shared meaning and abstraction direction. KEEP and placeholder traverse the same relation path as lattice levels.

Action history. Earlier selected decisions become count-blind utility-memory rows. Each current candidate queries this memory through one cross-attention block. There is no GRU, no selection-step embedding, and no future-action visibility. Empty history returns exactly zero.

§05

Privacy Signal and Controller

log-count prediction · profile scale · lambda

The privacy head predicts a distribution over log count for each lattice level. Approximate magnitude remains auditable, but only the predicted mean after profile-menu normalization enters the policy. KEEP and placeholder are fixed endpoints.

quantitydefinitionpolicy role
mu_logK(a)softplus(mu_raw(a))Predicted log-count mean.
sigma_logK(a)sigma_min + softplus(sigma_raw(a))Audit, calibration, and abstention diagnostic only.
p_hat(a)clip(mu_logK(a) / max_b mu_logK(b), 0, 1)Predicted profile-relative privacy progress used in deployed logits.
p(a)clip(log K(a) / max_b log K(b), 0, 1)Exact target from admitted own-profile counts. Training and diagnostics only.
g(lambda)log1p(lambda) / log1p(max Lambda)Fixed strength for one supported operating profile.

Combined logit

z(a, lambda) = u(a) + alpha · g(lambda) · p_hat(a)

alpha = softplus(alpha_raw)

After the dynamic legal mask, softmax converts z into the action distribution.

How privacy changes selection

log pi(a)/pi(b) = u(a)-u(b) + alpha·g(lambda)·(p_hat(a)-p_hat(b))

At lambda zero, privacy contributes exactly zero. At larger lambda, a candidate needs enough predicted privacy gain to overcome any utility disadvantage.

Why the head is pretrained. Profile-held-out count supervision forces the head to learn source-to-candidate abstraction before policy optimization. It must beat authored position, action mode and type, stable identity, and candidate-only baselines. The validated head is frozen during hybrid RL so the policy cannot bend p_hat into an uncalibrated preference.

Privacy pretraining loss. L_privacy = L_logcount_nll + rho · L_pairwise_rank + gamma · L_huber(p_hat, p). The likelihood preserves approximate count magnitude and uncertainty, the pairwise term checks ordering within a profile menu, and the Huber term calibrates the score consumed by the controller.

What exact counts do. Exact level_counts do not select actions directly and do not update the utility tower. They evaluate the current privacy contribution over the complete legal menu and update only the global scale alpha. Utility gradients oppose unbounded privacy pressure and also reach alpha, allowing one scalar to settle the useful range of the finite lambda menu.

§06

Reinforcement Learning Process

freeze · initialize · sample · measure · correct
FIG · T2: Training process and reward flow solid = rollout data · dashed = supervision or gradient ownership

Freeze first. The detector artifact, action menus, counts and provenance, accepted QA assertions, remote model, task prompt, extractor, reader, scorer, concurrency regime, and caches form one versioned environment. Changing any item invalidates cached utility, lambda calibration, and trained-policy comparisons together.

One lambda per episode. A seeded balanced Latin-cycle schedule gives every document every supported lambda profile over each complete block. Independent random sampling is disallowed because it can confound operating preference with corpus or type exposure.

One complete round trip per measured trajectory. Context assertions are scored on doc_p; delivered assertions are scored on out_final. Both contribute to the same fixed-denominator utility vector. Counterfactuals regenerate doc_p, rerun the remote task and local extraction, then rescore the complete vector.

§07

Credit Assignment and Loss

routing hints · RLOO · causal replacement

Document utility does not become one undifferentiated advantage. QA dependencies route cheap provisional evidence to the decisions that may matter. Sparse one-decision interventions then correct the highest-value uncertain cases.

pathcomputationrecipient
LinkedRLOO over assertions whose unique policy dependencies contain decision j.That linked decision once, even when several occurrences map to it.
ResidualRLOO over assertions with no policy dependency, including global and fixed-only effects.Added to every decision that already has linked credit.
FallbackRLOO over the complete assertion vector.Only decisions with no linked assertions. Missing QA never means zero utility.
CounterfactualMeasured delta_U between the selected action and one legal alternative.Replaces that decision's provisional term under the same 1/G weighting.

Utility objective

U(g,Q) = sum_q w_q u_g[q] / Z_d

A[g,j] = U[g,j] - loo_mean(U[-g,j])

No standard-deviation normalization. A constant assertion supplies no gradient.

Counterfactual pair

q_pair = pi(a) / (pi(a) + pi(b))

L_cf = -delta_U · (q_pair - 1/2)

The pairwise loss favors the measured better action and is bounded as confidence grows.

Exact count view. pi_count = softmax(mask(stopgrad(u) + alpha · g(lambda) · stopgrad(p_hat))). The dense objective is the negative expected exact target over every legal action, weighted by lambda / |D_d| and the same rollout-group factor 1/G. Only alpha receives this gradient.

Overall loss. L = mean_d L_utility(d) + L_count - beta · entropy + eta · KL(pi || pi_ref). Counterfactual terms replace their corresponding provisional utility terms; they are not averaged into a separate unweighted bonus.

Scheduler. Counterfactual budget first covers decisions with no linked assertions, then multi-decision links and uncertain or stale measured pairs, while reserving nonzero probability for every eligible decision. Adjacent finer or coarser actions are preferred, with a pre-registered minority of KEEP and placeholder endpoint tests.

Training Sequence and Gates

Lambda menu selection. Start at zero, then choose three to five supported values from observed per-document utility and count switch points. Values are snapped to observed thresholds and replayed. Redundant profiles are merged rather than padded with invented precision.

Encoder caveat. The pinned clinical encoder saw all ACI-BENCH documents during pretraining. ACI artifacts may support development diagnostics and pipeline training, but they cannot select the encoder or establish out-of-corpus generalization. Those claims require a non-ACI clinical validation corpus.

§09

Document Inference

local ranking · dynamic legality · remote round trip

Inference selects one supported lambda, walks frozen policy decisions once in first-occurrence order, and returns a complete action vector before any remote task call.

FIG · I1: Deployed document inference green = frozen/local · blue = ranker · amber = untrusted remote · dashed feedback = sequential state

One local pass. The caller chooses one supported lambda before ranking. The policy initializes empty selected-action memory and walks the frozen decision sequence. Dynamic legality removes any level fill already reserved or claimed. The model scores all actions in the complete menu, gathers the legal action IDs, and applies log_softmax. Deployment uses deterministic argmax.

Decision-level action, occurrence-level rewrite. Selecting one action updates every occurrence mapped to that decision. The selected utility relation, action mode, runtime type, and source-position pool become one history row for later decisions. Repeated occurrences do not create repeated policy steps.

Remote boundary. Ranking itself uses no QA probes, reader, reward model, exact count target, or counterfactual call. Only doc_p reaches the remote task model. The substitution record R stays local and combines with out_p to produce out_final.

§10

Boundaries and Audit

what the design means · what it does not prove

Normative invariants

  • Lambda zero exactly equals utility logits before masking.
  • True counts never enter semantic actor features.
  • Exact count gradients cannot update utility or memory.
  • Privacy-head training cannot update utility features.
  • QA links route credit but never certify causality.
  • Uncovered decisions never default to zero utility credit.

Open empirical questions

  • Can semantic log-count prediction transfer to unseen profiles?
  • Can one global alpha realize useful distinct operating points?
  • Does frozen candidate-conditioned attention expose enough context?
  • Does selected-action memory improve multi-decision utility?
  • Does higher count score track lower realized attacker success?
  • Does first-occurrence factorization create material order effects?

Repeated-context leakage. The exact document count score averages once per distinct policy decision, so repeated mentions do not multiply count reward. This is an explicit approximation, not a claim that repetition is harmless. Repeated values in different contexts may increase linkage or inference risk and require a future occurrence-aware attacker audit.

Fallback architecture. If semantic privacy transfer fails or stricter count auditability is required, the retained factorized fallback uses grounded type-normalized counts directly in a separate privacy branch. It remains count-blind on the utility side, but it does not offer the semantic prototype's transfer claim.

Verdict rule. Count score, KEEP rate, lattice depth, and lambda are diagnostics. A method is compared only by utility versus held-out attacker success at matched realized privacy and identical settings. If count score rises while attacker privacy worsens, the approximation is falsified in that region and the failure is reported rather than calibrated away.
